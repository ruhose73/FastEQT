# Fine-tuning EQTransformer на региональных данных

## Контекст и цель

Текущая модель EQTransformer обучена на глобальном датасете STEAD (1.2M трасс, преимущественно Калифорния).
Региональная сейсмика Северного Кавказа/Дагестана отличается по:
- типу датчиков (короткопериодные SM3-KV вместо широкополосных)
- характеристикам шума
- диапазону магнитуд (до −0.5)
- частоте дискретизации (50 Hz у большинства станций)

**Цель:** дообучить модель на региональном каталоге для улучшения recall и точности P/S пиков.

---

## Характеристики сети (из метаданных)

68 станций в 3 сетях: DA (Дагестан), RU, N0.

| Каналы | Частота | Кол-во станций | Примеры |
|--------|---------|----------------|---------|
| SH*    | 50 Hz   | 37             | DA.* сеть, RU.GLDR, RU.GUZR, RU.ZEI |
| EH*    | 100 Hz  | 16             | RU.BEYR, RU.DOMR, RU.SHA1, RU.VSLR |
| HH*    | 100 Hz  | 7              | N0.CEI, N0.DIGR, RU.NEUR |
| BH*    | 100 Hz  | 7              | RU.SOC, RU.NCK, RU.ANN, RU.GOFR |
| SL*    | 40 Hz   | 5              | N0.BTKR, N0.KMGR, N0.PRTR |

Все станции — 3-компонентные (Z, N, E). SL* станции (40 Hz) — исключить или ресемплировать.

---

## Данные для запроса в исследовательский центр

```
1. QuakeML каталог за [период: 1–3 года]
   - arrivals P и S по каждой станции (не только гипоцентры)
   - quality/weight пика для каждой фазы

2. MiniSEED непрерывные суточные файлы
   - все 3 компоненты (*Z, *N, *E)
   - все станции сети
   - тот же период

3. StationXML метаданные — уже есть в metadata/
```

### Почему непрерывные, а не нарезанные окна
Нарезанные окна не дают шумовых примеров. Шум нужен для обучения (целевое соотношение сигнал:шум = 1:1 или 1:2).

---

## Ожидаемый объём датасета

| Параметр | Оценка |
|----------|--------|
| Событий в каталоге | 1 000–1 500 |
| Станций на событие (среднее) | 8–15 |
| Сигнальных трасс | **8 000–20 000** |
| Шумовых трасс (1:1) | 8 000–20 000 |
| Итого | ~16 000–40 000 трасс |

Этого достаточно для fine-tuning, но недостаточно для обучения с нуля.

---

## Стратегия обучения

**Выбор: Fine-tune со всеми слоями (не замороженными)**

| Вариант | Применимость | Для нашего случая |
|---------|-------------|-------------------|
| С нуля | >100k трасс | Нет — мало данных |
| Fine-tune (заморозить нижние слои) | Домены близки (похожие инструменты, похожий шум) | Нет — инструменты другие |
| **Fine-tune (все слои)** | **8k–40k трасс, другие инструменты, другой шум** | **Да** |

Ключевой момент: маленький learning rate сохраняет pretrained знания о P/S волнах,
но позволяет адаптировать все слои под региональную специфику.

```python
learning_rate = 1e-4   # в 10x меньше чем при обучении с нуля
batch_size    = 32
epochs        = 50–80
early_stopping patience = 10
```

### Шаг 1. Парсинг QuakeML → таблица пиков

Скрипт: `core/quakeml_parser.py`

```python
# На выходе: DataFrame со столбцами:
# event_id | origin_time | lat | lon | depth | station | network |
# P_time   | S_time      | P_weight | S_weight
```

Проверить: среднее число пиков на событие. Если < 5 — данных мало, пересмотреть стратегию.
Если arrivals только гипоцентры без фаз по станциям — запросить каталог повторно.

---

### Шаг 2. Анализ каналов и маппинг станций

Скрипт: `core/station_mapper.py`

Для каждой станции из таблицы пиков:
1. Найти StationXML в `metadata/`
2. Определить активные каналы на момент события
3. Выбрать приоритет: EH* > HH* > BH* > SH* (по качеству для данного региона)
4. Зафиксировать sample rate
5. SL* (40 Hz) → пометить флагом `exclude=True` (слишком низкая частота)

Сохранить словарь: `{NET.STA: {channels: [...], sample_rate: N, exclude: bool}}`

---

### Шаг 3. Нарезка MiniSEED окон

Скрипт: `core/dataset_builder.py`

#### Параметры окна

```python
WINDOW_LEN  = 60.0   # секунд → 6000 сэмплов @ 100 Hz
P_OFFSET    = 5.0    # P-пик на сэмпле 500 (запас перед P)
TARGET_SR   = 100.0  # Hz (EQTransformer стандарт)
```

#### Алгоритм для каждого пика

```
win_start = P_time - P_OFFSET
win_end   = win_start + 60.0

1. Определить суточный файл по дате win_start
2. Если окно пересекает полночь → загрузить два суточных файла
3. ObsPy: st = read(file); st.merge(fill_value=0); st.slice(win_start, win_end)
4. Проверить: len(trace) >= 5500 сэмплов после ресемплинга
5. Препроцессинг (см. ниже)
6. Записать в HDF5
```

#### Препроцессинг (порядок важен)

```python
st.detrend('demean')
st.taper(max_percentage=0.05, type='cosine')
st.filter('bandpass', freqmin=1.0, freqmax=45.0, corners=4, zerophase=True)
st.resample(100.0)                          # 50→100 Hz или 40→100 Hz
arr /= np.max(np.abs(arr)) + 1e-10         # нормализация по max
```

**Почему не удалять инструментальный отклик:** EQTransformer обучен на нормализованных велосиметрических трассах.
Bandpass + нормализация даёт эквивалентный результат без риска артефактов от response removal.

#### Фильтры качества (отбросить трассу если)

| Условие | Значение |
|---------|----------|
| P_time отсутствует | обязательное поле |
| s_sample - p_sample < 30 | S слишком близко к P (шум) |
| s_sample > 5500 | S уходит за конец окна |
| max(abs(arr)) == 0 | мёртвый канал |
| Длина трассы < 5500 сэмплов | неполная запись (пробел) |

### Шаг 4. Шумовые окна

В тех же суточных файлах, что и сигнальные:

```
1. Собрать все P_time для данной станции
2. Найти промежутки между событиями > 120 с
3. В каждом промежутке случайно выбрать win_start
   (окно не должно пересекаться с ближайшими событиями ±60 с)
4. Загрузить и препроцессить аналогично
5. p_arrival_sample = -1, s_arrival_sample = -1
6. trace_category = 'noise'
```

Целевое соотношение: **1 шумовое окно на 1 событие** (ratio настраивается).

---

### Шаг 5. Сборка HDF5

Формат совместим с `EQTransformer/core/trainer.py`:

```
/data/{trace_name}    float32    shape=(6000, 3)   # [E/1, N/2, Z]
```

Атрибуты каждой трассы:

```python
{
    'trace_name':        str,   # уникальный ключ: NET.STA.YYYY.DDD.HHmm
    'network':           str,
    'station':           str,
    'instrument_type':   str,   # EH, SH, HH, BH
    'station_lat':       float,
    'station_lon':       float,
    'station_elv':       float,
    'p_arrival_sample':  int,   # 500 для событий, -1 для шума
    's_arrival_sample':  int,   # вычислено или -1
    'coda_end_sample':   int,   # s_sample + 200 (эвристика)
    'snr_db':            float, # SNR в окне P
    'trace_start_time':  str,   # ISO8601
    'trace_category':    str,   # 'earthquake_local' | 'noise'
    'source_id':         str,   # publicID из QuakeML
    'source_magnitude':  float, # -1 если нет
    'p_weight':          float, # из QuakeML arrivals
    's_weight':          float,
}
```

Companion CSV: те же поля, одна строка на трассу — нужен для `trainer()`.

### Шаг 7. Fine-tuning

```python
from EQTransformer.core.trainer import trainer

trainer(
    input_hdf5    = 'training_data/train.hdf5',
    input_csv     = 'training_data/train.csv',
    input_testset = 'training_data/test.hdf5',
    input_model   = 'pre_trained_models/EqT_original_model.h5',
    output_name   = 'regional_model_v1',
    epochs        = 70,
    batch_size    = 32,
    loss_weights  = [0.05, 0.40, 0.55],  # [detector, P, S]
    loss_types    = ['binary_crossentropy'] * 3,
    patience      = 10,
    gpuid         = 0,
    gpu_limit     = 0.9,
    augmentation  = True,
)
```

`loss_weights`: P и S важнее детектора — региональная специфика важна именно в точности пиков.

Следить за: `val_P_loss` и `val_S_loss` отдельно. Если растут — снизить lr до 5e-5.

## Известные сложности

| Проблема | Решение |
|----------|---------|
| 50 Hz станции (37 шт.) | Ресемплинг → 100 Hz через ObsPy |
| 40 Hz станции (SL*, 5 шт.) | Исключить из датасета |
| Окно пересекает полночь | Загружать два суточных файла, merge |
| Пробелы в записях | `st.merge(fill_value=0)`, проверять длину после slice |
| Мало данных если M < 0 записаны только на 3–5 ближних станциях | Снизить порог quality до 0.5, не фильтровать жёстко |
| QuakeML без arrivals по станциям | Запросить повторно с явным указанием нужности arrivals |
