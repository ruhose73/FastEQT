# validate_associator_v2 — Оценка origin time без координат события

## Постановка задачи

Ассоциатор (`run_associator_v2`) выдаёт XML с P/S-пиками по станциям, но не вычисляет
origin time события — только `min(p_arrival_time)` первой станции. Задача: оценить
истинное время начала события (T0) используя только пики EQT, без координат эпицентра,
и сравнить с каталогом.

Это важно для онлайн-режима: при реальном мониторинге координаты события неизвестны
до локализации, поэтому T0 должен оцениваться из одних пиков.

---

## Формула S-P

Для каждой станции с P и S пиком:

```
ΔT   = Ts − Tp
R    = Vp·Vs / (Vp − Vs) · ΔT     (гипоцентральное расстояние)
T0   = Tp − R / Vp  =  Ts − R / Vs    (математическое тождество)
```

Параметры: `Vp=6.0 км/с`, `Vs=3.4883 км/с`, `k=8.333 км/с`.

---

## Проблема: систематическое смещение T0

EQT обучен на пиках амплитуды волны, а не на моменте прихода. Это вносит
систематическую положительную ошибку:

```
δTp — запаздывание P-пика EQT
T0_ошибка = Vp / (Vp − Vs) · δTp ≈ 2.4 · δTp
```

Если EQT запаздывает на 1–5 с, T0 смещается на 2–12 с вперёд относительно каталога.
Ошибка амплифицируется коэффициентом ~2.4.

---

## Опробованные методы

### 1. T0min — ближайшая станция

T0 берётся от станции с минимальным ΔT (S-P). Логика: чем ближе станция, тем меньше
накопленная ошибка скоростной модели.

**Результат (май 2024, 10 событий):** MAE ≈ **14.8 с**. Работает плохо — одна
ближайшая станция может иметь плохой пик.

---

### 2. T0raw — среднее по всем станциям без фильтра

Простое среднее T0 по всем станциям с P+S пиком.

**Результат:** MAE ≈ **6.1 с**. Хуже σ-фильтрованного среднего из-за выбросов.

---

### 3. T0mean — σ-фильтрованное среднее (основной метод)

Алгоритм:
1. Вычислить T0 для каждой станции
2. Найти медиану
3. Вычислить σ = pstdev(T0)
4. Отбросить станции где `|T0 − median| > sigma_mult · σ`  (sigma_mult=2.0)
5. Среднее по оставшимся inliers

**Результат:** MAE ≈ **4.1 с**. Значительно лучше T0min.

---

### 4. T0wmean — взвешенное среднее 1/ΔT²

Вес = `1 / dt_sp²`: ближние станции (малый S-P) получают больший вес.

**Результат:** MAE немного хуже T0mean. Причина: ближайшая станция необязательно
имеет лучший пик EQT. Метод оставлен в коде, но не рекомендуется.

---

### 5. T0prb — взвешенное среднее по p_probability

Вес = `p_probability` из `X_prediction_results.csv` (EQT уверенность в P-пике).

**Результат:** MAE ≈ **3.9 с**. Незначительное улучшение относительно T0mean.

---

### 6. T0psnr — взвешенное среднее по p_probability × p_snr ← **текущий лучший**

Вес = `p_probability × p_snr`. Физический смысл: высокий SNR означает чёткий
импульсный вход P-волны → пик EQT точнее.

**Результат:** MAE ≈ **1.9 с** (10 событий май 2024, Ms ≥ 1.5).

| Метод   | MAE    | max ошибка |
|---------|--------|------------|
| T0min   | 14.8 с | —          |
| T0raw   | 6.1 с  | —          |
| T0mean  | 4.1 с  | 13.2 с     |
| T0prb   | 3.9 с  | 12.8 с     |
| **T0psnr** | **1.9 с** | **6.5 с** |

## Двухскоростная модель (--dual-vel)

Попытка разделить Pg/Sg (R < 150 км) и Pn/Sn (R ≥ 150 км, Vp=8.0, Vs=4.6).
При spLimit=45 станции могут быть до 375 км → Pn-режим возможен.

**Результат:** улучшение T0 < 1.5 с, что меньше дисперсии от ошибок EQT.
Метод реализован (`estimate_origin_times_v2`), но не даёт значимого выигрыша.

## Матчинг с каталогом: --match-by

Матчинг выбирает ближайшую ассоциацию у которой `|T0_assoc − T0_catalog| ≤ window`
**и** число станций ≥ `--min-stations`. Если в окно попадают несколько — берётся
с минимальным `|diff|`.

`T0_assoc` определяется `--match-by`:
- `min` → T0 ближайшей станции (по ΔT)
- `mean` → σ-фильтрованное среднее
- `psnr` → взвешенное p_prob×p_snr (с откатом на mean, затем min если None)

**Важно:** при `--match-by psnr` колонка `T0min,с` показывает то же значение что
и `T0psnr,с` — обе колонки выводят `dt_sec = ot_match − cat_t`.

## Проблема биmodal-распределения T0 (событие #4)

Событие 2024-05-14 15:38:43, T0psnr = **+4.2 с** (после coherence_tolerance=5).

С tolerance=15 ассоциатор объединял пики двух разных событий в одно окно.
С tolerance=5 — разделил: событие #4 теперь содержит только ранний кластер.

---

## Улучшение ассоциатора: coherence_tolerance

```
|Tp_A − Tp_B| ≤ dist(A,B) / Vp + tolerance
```

**Старое значение (15 с):** позволяло пикам двух разных событий (разделённых на
25–35 с) пройти проверку при далеко расположенных станциях.

**Новое значение (5 с):** покрывает ошибку EQT (~2 с) + модель скоростей (~2 с)
с запасом.

**Итог:** tolerance=5 дало +1 recall (11/13 vs 10/13) и +17% событий ML≥1.5
за счёт расщепления биmodal-ассоциаций на отдельные чистые события.

**Ограничение:** не помогает когда P-приходы двух событий случайно совпадают
по времени (см. событие 2024-05-06 ниже).

## Событие 2024-05-06 12:25:10 — неустранимый miss

Анализ через `--show-picks`:

| Станция | R,км  | Tp0              | Δ от каталога |
|---------|-------|------------------|---------------|
| **SHA1** | 296.8 | 12:25:09.10 | **−0.9 с** ← правильная |
| NVPR    | 125.6 | 12:25:35.33 | +25.3 с |
| DVE     | 293.2 | 12:25:45.18 | +35.2 с |
| SRGR    | 22.1  | 12:25:50.94 | +40.9 с |
| DIGR    | 31.2  | 12:26:09.28 | +59.3 с |
| KMKR    | 26.4  | 12:26:34.24 | +84.2 с |

SHA1 (296 км) поймала правильное событие. Пять ближних станций детектировали
другое событие ~40–85 с позже — вероятно радиационная диаграмма (SHA1 в направлении
максимума, ближние станции в узловой плоскости).

**Почему coherence_tolerance=5 не помогает:** P-волна от каталожного события до SHA1
(296 км) прибывает ~12:25:59. P-волна второго события до SRGR (22 км) — ~12:25:54.
Разница ~4 с < dist(SHA1, SRGR)/6 + 5 → пара проходит когерентность случайно.

**Почему σ-фильтр не помогает:** σ = 26.6 с, порог 2σ = 53.2 с — все 6 станций
(включая KMKR с +84 с) проходят.

**T0psnr = +19.9 с** — компромисс: SHA1 с наибольшим p_prob (0.840) тянет к −0.9 с,
пять "неправильных" станций тянут к +40…+84 с.

**Исправить параметрами ассоциатора нельзя:** SHA1 одна правильно детектировала событие.
Любой разумный pair_n требует ≥2 станций.

## Дальнейший план улучшений

### Приоритет 1 (выполнен): coherence_tolerance=5

Запущено, результат: Recall 11/13, MAE T0psnr ≈ 1.9 с.

---

### Приоритет 2: estimate_uncertainty=True (MC Dropout)

**Что даёт:** `p_uncertainty` — std предсказания P-пика по N стохастическим
проходам модели с включённым dropout. Вес `1/σ²` математически оптимален.

**Текущее состояние:** не работает. `model.predict()` отключает dropout →
std=0 у всех проходов.

**Что нужно:** создать `_gen_writer_mem_non_hdf_v11` с циклом `model(batch, training=True)`.

**Риск:** EQT может быть одинаково уверен в правильных и неправильных пиках.

---

### Приоритет 3: T0 coherence filter в ассоциаторе

Добавить проверку совместности T0-оценок на уровне ассоциатора:
1. Вычислить T0 из S-P для каждой станции
2. Если spread(T0) > порог — итеративно удалять станцию, дальше всего от медианы T0
3. Продолжать до spread < порог или N < pair_n

Для события 2024-05-06: разделит кластеры (spread=85 с >> порога 15–20 с), но
SHA1 останется одна — ниже pair_n → событие будет пропущено.

## Про ML_SIGMA vs DEFAULT_SIGMA

| Константа | Где используется | Что фильтрует |
|-----------|-----------------|---------------|
| `DEFAULT_SIGMA` (--sigma) | `sigma_filter()` в validate_associator_v2 | T0-оценки станций → σN |
| `ML_SIGMA` | `compute_ml()` в validate_associator_v2 | per-station ML-оценки |
| `ML_OUTLIER_SIGMA` | `_filter_by_sigma_v2()` в ml_filter_v4 | per-station ML при фильтрации XML |

Изменение `ML_OUTLIER_SIGMA` в `ml_filter_v4.py` **не требует пересборки кэша** —
кэш хранит сырые амплитуды `(pub_id, sta) → A_meters`. Достаточно перезапустить
`ml_filter_v4.py`.

## Важный контекст

- **assoc_input/ перезаписывается** при каждом запуске `core/associator.py`, но данные
  те же (детектор не перезапускался) — `--prob-dir` для обоих XML указывает на один каталог.
- **coherence_tolerance=5 vs 15**: сырые ассоциации схожи (62к vs 65к). Главный эффект —
  расщепление биmodal-событий на отдельные чистые ассоциации (+17% событий ML≥1.5, +1 recall).
- **Станционные поправки снижают ML на ~0.12** (медиана). Без поправок: 5398 событий ML≥1.5;
  с поправками: 2626 (старый XML) / 3274 (новый XML).
- **Разница 2626 vs 3274** объясняется тем, что tolerance=5 расщепляет биmodal-события:
  каждое из двух подсобытий получает корректный ML, больше проходит порог 1.5.
