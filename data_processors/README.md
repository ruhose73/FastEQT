# data_processors/ — Подготовка входных данных

Скрипты для преобразования сырых сейсмических данных (SDS-архив) и метаданных станций (StationXML) в формат, пригодный для обработки пайплайном EQT.

Запускать из папки `data_processors/`: `python main.py` (пути внутри заданы относительно этой папки).

---

## Модули

### `main.py` — Точка входа

Координирует запуск двух независимых процессоров: метаданных станций и сейсмических файлов. Каждый шаг выполняется только если **все** связанные с ним пути уже существуют — никакие директории или файлы `main.py` сам не создаёт.

**Настроенные пути** (жёстко заданы в начале файла):

```python
metadata_xml_folder_path     = '../../../../science/geodata/Metadata/RU'
json_stationlist_output_path = 'json2/station_list_RU.json'
geofile_input_directory      = '../../../science/geodata/SDS/2024/RU'
geofile_output_directory     = 'geofiles'
```

**Шаг 1 — Метаданные:**
Условие запуска — `metadata_xml_exist AND json_stationlist_exist`, где `json_stationlist_exist = os.path.exists(json_stationlist_output_path)`.

⚠️ **Важная особенность:** это проверка существования **выходного** JSON-файла, а не его директории. `combine_inventories_to_json()` открывает файл в режиме `'w'`, так что для первого запуска на новом месте файл `json2/station_list_RU.json` нужно создать заранее вручную (пустым), иначе шаг молча пропускается с сообщением `JSON False`.

**Шаг 2 — Сейсмические файлы:**
Условие запуска — обе директории (`geofile_input_directory`, `geofile_output_directory`) уже существуют. Список станций берётся автоматически: `get_directories()` возвращает имена всех подпапок первого уровня во входной SDS-директории (это и есть коды станций), и они передаются в `geofile_processor()`.

Если какое-то из условий не выполнено, скрипт печатает, какого именно пути не хватает (`print("XML", ...)` / `print("INPUT", ...)` и т. п.), и просто переходит к следующему шагу — выполнение не прерывается.

```bash
python data_processors/main.py
```

### `geofile_processor.py` — Конвертер SEED-файлов

Преобразует суточные SEED-файлы из SDS-архива в формат имён файлов, который принимает EQTransformer, и одновременно фильтрует их по диапазону дат.

#### Формат хранения SDS (SeisComP Data Structure)

Это стандартная раскладка непрерывных волновых данных по каталогам, которую использует SeisComP, ObsPy (`obspy.clients.filesystem.sds`) и многие сейсмологические сети. Именно её на входе ожидает `geofile_processor.py`:

```
<SDSdir>/YEAR/NET/STA/CHAN.TYPE/NET.STA.LOC.CHAN.TYPE.YEAR.DAY
```

- **YEAR** — четырёхзначный год; отдельная папка на каждый год.
- **NET** — код сети (FDSN network code), например `RU`.
- **STA** — код станции, например `SOC`.
- **CHAN.TYPE** — подпапка вида `BHE.D`: код канала (`BHE`, `BHN`, `BHZ`, ...) + тип данных (`D` = непрерывные волновые данные, обычно miniSEED).
- Имя файла на нижнем уровне — `NET.STA.LOC.CHAN.TYPE.YEAR.DAY`: один файл на пару станция/канал за одни сутки, где `DAY` — порядковый номер дня в году (day-of-year, 001–365/366). `LOC` (код локации) — часть имени файла, а не отдельная папка; может быть пустым (тогда в имени идут две точки подряд, `..`) или двухсимвольным (`U4`, `XX` и т. п.) — это зависит от конкретной станции, а не от формата SDS как такового.

Пример: `RU.SOC.U4.BHE.D.2024.001` — сеть `RU`, станция `SOC`, локация `U4`, канал `BHE`, тип `D`, год 2024, 1-й день года.

`geofile_processor()` принимает на вход путь до уровня `NET` (`base_directory`) и список кодов станций (`subdirectories` — подпапки `STA`), дальше сам рекурсивно спускается через `CHAN.TYPE` до файлов. EQT же ожидает не day-of-year, а явные ISO-таймстемпы начала и конца суток в имени файла — этим преобразованием и занимается модуль.

**Диапазон дат задаётся константами вверху файла** (не параметр функции):

```python
date_from = datetime(2024, 4, 1)
date_to   = datetime(2024, 6, 1)   # не включается
```

`geofile_processor(subdirectories, base_directory, destination_base_directory)` — что делает:

1. Для каждой станции (`subdir` из списка `subdirectories`) создаёт `destination_base_directory/{station}` (`os.makedirs(..., exist_ok=True)`), если исходной папки станции нет — печатает предупреждение и пропускает её.
2. Рекурсивно обходит папку станции через `os.walk` (значит подхватит файлы из любых вложенных подпапок, не только верхнего уровня).
3. Для каждого файла берёт последнюю точечную часть имени (`file_name.split('.')[-1]`) как номер дня в году и проверяет, что это число 1–365.
4. Переводит номер дня в календарную дату **относительно `date_from.year`** (год всегда берётся из константы `date_from`, а не из имени файла) и проверяет попадание в `[date_from, date_to)`.
5. Формирует новое имя: `{base_name}__{start}__{end}`, где `base_name` — имя файла без двух последних точечных частей (`.2024.001`), а `start`/`end` — начало и конец суток в формате `%Y%m%dT%H%M%SZ`.
6. Копирует (`shutil.copy2`) файл под новым именем в плоскую папку станции назначения.

**Формат преобразования:**
```
RU.SOC.U4.BHE.D.2024.001  →  RU.SOC.U4.BHE.D__20240401T000000Z__20240402T000000Z
```

Файлы вне диапазона `date_from`–`date_to` или с некорректным номером дня просто не копируются — отдельной фильтрации не требуется.

Примечание: в коде вычисляется `folder_name = os.path.basename(root)` (имя вложенной подпапки при рекурсивном обходе), но эта переменная нигде не используется — вложенная структура при копировании не сохраняется, все файлы одной станции попадают в один плоский каталог назначения.

### `metadata_processor.py` — Конвертер метаданных станций

Преобразует XML-файлы метаданных сети (StationXML / FDSN) в единый JSON-файл, которым пользуются детектор и ассоциаторы для получения координат станций и списка каналов.

**Выходной формат JSON** (один файл, ключ — код станции):
```json
{
  "SOC": {
    "network": "RU",
    "channels": ["BHE", "BHN", "BHZ"],
    "coords": [43.57, 39.763, 54.0]
  }
}
```

**`read_inventory_file(file_path)`** — читает один XML-файл через ObsPy `read_inventory()` и строит из него словарь `{station_code: {...}}`:

- Для каждой сети (`network`) код станции берётся как `network.stations[0].code` — то есть **как ключ используется код только первой станции в сети**, даже если в этой сети (в этом конкретном XML) перечислено несколько станций.
- Координаты (`coords = [lat, lon, elevation]`) берутся из объекта `station` и перезаписываются на каждой итерации внутреннего цикла `for station in network` — в результате в `coords` попадают координаты **последней** станции цикла, а не обязательно той, чей код использован как ключ.
- Список каналов собирается похожим образом: для каждого канала есть проверка `channel.start_date >= last_date`, где `last_date` — start_date **последнего канала по порядку в списке** (а не максимальная дата среди всех каналов — цикл, который это вычисляет, просто перезаписывает `last_date` на каждой итерации). Смысл проверки — оставить только каналы, актуальные на момент последней эпохи метаданных станции, но при непредсказуемом порядке каналов в XML результат зависит от их фактического порядка.

  ⚠️ Из-за этих двух особенностей модуль рассчитан на XML-файлы с ровно одной станцией на сеть (типичный экспорт FDSN station-service по одной станции) — на файлах с несколькими станциями в одной сети координаты и каналы разных станций могут перемешаться под одним ключом.

**`combine_inventories_to_json(xml_folder_path, json_output_path)`** — обходит все файлы `*.xml` в папке (`os.listdir`, без рекурсии по подпапкам) и для каждого вызывает `read_inventory_file`:

- если код станции встречается впервые — данные добавляются целиком;
- если станция уже есть (её метаданные встретились в другом XML-файле) — список `channels` дополняется через `extend` (без дедупликации, возможны повторы), а `coords` **не** обновляются и остаются от первого встреченного файла.

Результат сохраняется одним JSON-файлом (`json.dump(..., indent=4)`) по пути `json_output_path`; если директория назначения не существует, перехватывается `FileNotFoundError` с понятным сообщением об ошибке.

Готовый JSON-файл (например, `json2/station_list_RU.json`) используется детектором и ассоциаторами для геолокации станций и вывода координат в CSV.
