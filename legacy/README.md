# legacy/ — Устаревшие скрипты

Ранние/заброшенные версии пайплайна, сохранённые для справки. Не используются в текущей обработке, за исключением `cutter-v5.py`, который `core/gpu_pipeline.py` всё ещё может грузить через `importlib` (сам `gpu_pipeline.py` сейчас работает через `core/detector.py`, не через него).

---

## Детектор

- **`detector.py`**, **`cpu_pipeline.py`**, **`gpu_pipeline.py`** — версии без CLI, до перехода на конфигурацию через флаги командной строки. Заменены одноимёнными файлами в `core/`: та же логика обработки, но список станций/пороги/пути задаются флагами, а не константами в начале файла; из `detector.py` дополнительно убрана мёртвая `process_station_v2` и неиспользуемая константа `MAX_WORKERS`, из `gpu_pipeline.py` — неиспользуемая `get_threads_to_use()` (дублировала `core/threads.py`).
- **`cutter-v5.py`** — последняя legacy-версия детектора до перехода на `core/detector.py`; `main_v7` (последовательно) / `main_v10` (для `importlib`).
- **`geofile_cutter.py`** — самый ранний сплиттер сегментов, без генераторного режима, HDF5 на диск.
- **`preprocessor.py`** / **`predictor.py`** — оригинальный двухфазный EQT-пайплайн (HDF5 на диск), отказались из-за I/O (~12ч/месяц).
- **`cutter-v2.py`** / **`cutter-v3.py`** — ранние параллельные препроцессоры через `multiprocessing.Pool`, HDF5 на диск.
- **`thread_executor.py`** — ранний многопоточный раннер поверх двухфазного HDF5-пайплайна. Заменён `core/cpu_pipeline.py`.

## Ассоциатор

- **`associator.py`** — оригинальный `run_associator()`, группировка по `event_start_time` (проблема границы бина).
- **`associator_v2.py`** — то же + пороговый стейджинг, без скользящего окна.
- **`associator_v3.py`** — версия до перехода на CLI: тот же алгоритм (`run_associator_v2`, скользящее окно + `_coherent_subset`), но без CLI — весь код выполнялся построчно на верхнем уровне модуля, пороги/пути/список станций были константами. Заменена одноимённым файлом в `core/` (не `_v1`/`_v2` — те уже заняты другим смыслом, отсюда номер `_v3`, продолжающий существующую, пусть и не строго хронологическую, нумерацию).
- **`sector_associator.py`** — секторный (запад/восток) ассоциатор; проигрывал по recall обычному сетевому (33/49 vs 36/49). Заменён `core/associator.py`.

Все три заменены `core/associator.py` (`run_associator_v2`, скользящее окно + `_coherent_subset`).

## Магнитуда (ML)

- **`ml_filter_v1.py`** (был `core/ml_filter.py`) → **`ml_filter_v2.py`** → **`ml_filter_v3.py`** → **`ml_filter_v4.py`** — цепочка версий ML-фильтра ассоциаций; история ошибок и переход v1→v2 (grid-search R, окно P-волны и т.д.) были в `ml_filter_v1_v2_notes.md` (удалён, содержание свёрнуто сюда). `ml_filter_v4.py` перенесён сюда — CLI-чистка того же алгоритма (без изменений формулы) ушла в **`core/ml_filter_v5.py`**, `v4.md` тоже здесь для истории. Заменены **`core/ml_filter_v5.py`**.
- **`magnitude_estimator.py`** — ранняя оценка Ml через grid-search локацию по P-временам; путь к данным от неактуальной конфигурации. Заменён связкой `core/sta_correction_estimator.py` + `core/ml_filter_v5.py`.
- **`sta_correction_estimator.py`** — версия до чистки: содержала неиспользуемые `ML_OUTLIER_ABS` (докстринг `compute_event_ml_detail_v2` заявлял её как условие отсечения выбросов, в коде не применялась) и `_PAZ_WA`. Заменена одноимённым файлом в `core/` — тот же CLI/алгоритм, эти две мёртвые константы убраны.
- **`magnitude_filter.py`** — альтернативный прокси-фильтр по SNR с поправкой на расстояние вместо полноценной формулы ML. Заменён формулой Дягилева в `ml_filter_v2`+.
- **`ml_calibrate.py`** — регрессионная калибровка коэффициентов формулы ML поверх `sta_corrections_detail.csv`. Отдельный инструмент проверки, не встроен ни в один рабочий вызов.

## Валидация

- **`validate_associator.py`** — валидатор XML по каталогу, v1. Раньше вызывался из `ml_filter_v4.py --validate`; реальная проверка всегда шла отдельно через `core/validate_associator_v2.py` — флаг убрали. Заменён `core/validate_associator_v2.py`.
- **`validate_catalog.py`** — сравнение CSV одной станции с каталогом (не XML сети). Ни разу не менялся, нигде не вызывается — только шаг «на будущее» в планах по дообучению модели.
- **`catalog_stats.py`** — G-R статистика каталога. Хардкодит несуществующее сейчас имя файла каталога — упадёт при запуске. Разово использовался рано в проекте.
- **`threshold_tuner.py`** — сеточный поиск порогов на готовых CSV. Дефолтный путь — от давно не существующей директории (`output/`, legacy `cutter-v5.py`).

## Временное

- **`_tmp_missed2.py`** — черновик разбора конкретных пропущенных событий каталога. Никогда не был частью пайплайна.
