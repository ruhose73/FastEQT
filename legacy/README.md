# legacy/ — Устаревшие скрипты

Ранние версии пайплайна, сохранённые для справки. Не используются в текущем процессе обработки, за исключением `cutter-v5.py`, который загружается из `core/gpu_pipeline.py` через `importlib`.

---

## Модули

### `cutter-v5.py` — Последняя legacy-версия детектора

Финальная версия скрипта обработки до перехода на `core/detector.py`. Содержит историю всех функций (v1–v7) и две активные точки входа: `main_v7` — для последовательной обработки одной станции (вызывается из `__main__`), `main_v10` — вызывается из `core/gpu_pipeline.py` через `importlib` для параллельной обработки. Функции обработки идентичны тем, что перенесены в `detector.py`.

### `geofile_cutter.py` — Первый сплиттер сегментов

Самая ранняя версия нарезки суточных потоков на сегменты. Читает файлы через ObsPy, нарезает на фиксированные интервалы и сразу запускает оригинальный `preprocessor()` — с записью HDF5 на диск. Не имеет генераторного режима, загружает все сегменты в память сразу.

### `preprocessor.py` — Оригинальный препроцессор

Обёртка вокруг оригинального EQT-препроцессора (`preprocessor()` из `hdf5_maker.py`). Записывает предобработанные данные в HDF5-файлы на диск. Представляет первый шаг старого двухфазного пайплайна (preprocessor → predictor), от которого отказались из-за I/O-узкого места (~12 часов / месяц).

### `predictor.py` — Оригинальный предиктор

Вызывает оригинальный EQT `predictor()`, который читает HDF5-файлы с диска и записывает CSV-результаты. Второй шаг старого двухфазного пайплайна. Параметры детекции жёстко заданы в файле.

### `cutter-v2.py` — Ранний параллельный препроцессор

Первая попытка параллельной обработки через `multiprocessing.Pool`. Использует `preprocessorV3` и передаёт сегменты как кортежи воркерам через очередь. Прямой предшественник cutter-v3.

### `cutter-v3.py` — Улучшенный параллельный препроцессор

Доработанная версия cutter-v2 с отдельным лог-файлом обработки и исправленным форматом передачи сегментов воркерам. По архитектуре аналогичен v2, но стабильнее. Оба варианта работают через HDF5 на диске.

### `associator.py` — Оригинальный ассоциатор

Простейший скрипт-запуск оригинального `run_associator()` из EQTransformer. Читает CSV из папки `detections_hdfs`, фиксированный временной диапазон январь 2024. Использует оригинальный алгоритм группировки по `event_start_time`, который имеет проблему скользящего окна. Заменён на `core/associator.py`.

### `associator_v2.py` — Ассоциатор с пороговым стейджингом

Добавляет фильтрацию по порогам (DET ≥ 0.7, P ≥ 0.3, S ≥ 0.2) перед запуском оригинального `run_associator()`. Промежуточный вариант перед переходом на `run_associator_v2` со скользящим окном. Список из 10 станций зафиксирован в конфигурации.

### `thread_executor.py` — Первый многопоточный раннер

Ранняя версия параллельной обработки нескольких станций через `concurrent.futures`. Использует оригинальный двухфазный пайплайн (HDF5): вызывает `preprocessor()` и `predictor()` последовательно для каждой станции в отдельном потоке. Прямой предшественник `core/cpu_pipeline.py`.
