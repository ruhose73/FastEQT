# EQTransformer — Высокопроизводительный пайплайн обработки сейсмических данных

> Форк [smousavi05/EQTransformer](https://github.com/smousavi05/EQTransformer) с полностью переработанным пайплайном для продакшн-масштабного непрерывного мониторинга сейсмичности.

---

## Обзор

Данный форк расширяет оригинальный EQTransformer (EQT) полностью **in-memory, GPU-ускоренным пайплайном**, который заменяет дисковую HDF5-архитектуру. Результат — ускорение обработки примерно в **35 раз**: один месяц данных с одной станции обрабатывается за **~20 минут** вместо ~12 часов при полном сохранении точности детекции.

Система протестирована на региональной сейсмической сети района Сочи (Кавказ, Россия) — 12 станций, эталонный каталог 49 событий за январь 2024 года.

**Лучший достигнутый результат: 37 из 49 событий каталога (75.5%)**

---

## Ключевые улучшения

### 1. In-Memory пайплайн

Оригинальный EQT записывает предобработанные данные в HDF5-файлы на диск, затем читает их обратно для инференса. На наборах данных масштаба месяца это создаёт серьёзное I/O-узкое место.

Новый пайплайн полностью исключает диск из цикла обработки:

```
SEED-файлы → ObsPy (RAM) → preprocessorV6_mem() → model.predict() → строки CSV
```

- `preprocessorV6_mem()` возвращает Python-словари вместо записи в HDF5
- `predictor_mem_non_hdf_load_model_v4()` принимает массивы напрямую из памяти
- `_gen_writer_mem_non_hdf_v10()` возвращает строки результатов без записи в файл
- Генератор `geofile_splitter_multi_chanels_v2()` выдаёт по одному 10-минутному сегменту за раз — RAM остаётся ограниченным независимо от длины набора данных

Потребление памяти стабильно: каждый сегмент удаляется после обработки, дневной поток ObsPy освобождается только после того, как все его сегменты обработаны (важный нюанс: ObsPy `slice()` возвращает представления, поэтому поток должен оставаться живым до завершения генератора).

| Метрика | Оригинал | Данный форк |
|---|---|---|
| Модель I/O | HDF5 на диск | In-memory |
| Время обработки / месяц (SOC) | ~12 часов | **~20 минут** |
| Ускорение | 1× | **~35×** |

---

### 2. Активация cuDNN для LSTM-слоёв

Модель EQT содержит 4 LSTM-слоя, обученные с `recurrent_dropout=0.2` и `implementation=1`. Оба параметра блокируют cuDNN, заставляя TensorFlow использовать медленную обобщённую CUDA-реализацию.

Оригинальный EQT не предоставляет механизма для исправления этого. Данный форк патчит модель **in-place после загрузки**, не затрагивая сохранённые веса и архитектуру:

```python
# recurrent_dropout и implementation — read-only @property на уровне слоя LSTM.
# Изменяемые значения живут в lstm.cell.
lstm.cell.recurrent_dropout = 0.0
lstm.cell.implementation = 2
```

Для `Bidirectional`-слоёв патчатся оба направления — `forward_layer.cell` и `backward_layer.cell`. Всего 6 ячеек. Патч прозрачен для всего последующего кода и реализован в `load_model_cudnn_v2()`.

**Результат:** `model.predict()` работает с cuDNN LSTM-ядрами, что подтверждается записью `Loaded cuDNN version 8100` в логах TF.

---

### 3. Оптимальное батчирование предсказаний

TensorFlow имеет фиксированные накладные расходы ~0.3 с на каждый вызов `model.predict()`. Оригинальный пайплайн вызывает predict для каждого 60-секундного окна отдельно.

Новый пайплайн батчирует все окна 10-минутного сегмента в один вызов:

| Стратегия | Вызовов / месяц | Время выполнения |
|---|---|---|
| На каждое 60-с окно | ~87 000 | ~8.5 часов |
| На 10-мин сегмент (13 окон) | ~8 150 | **~20 минут** |

---

### 4. Параллельная многостанционная обработка

Для одновременной обработки нескольких станций реализованы два режима параллельного выполнения.

#### `core/detector.py` — Основной GPU-пайплайн

Автономный скрипт со встроенным `ProcessPoolExecutor`. Каждый рабочий процесс загружает модель **один раз** через паттерн `initializer`, после чего последовательно обрабатывает свои станции. Такой подход устраняет многократную инициализацию TF и позволяет эффективно использовать VRAM.

```bash
conda activate eqt3
python core/detector.py
```

По умолчанию: `MAX_WORKERS=6`, 12 станций, январь 2024, вывод в `data-in-memory/output_gpu/`.

Для обработки одной станции достаточно отредактировать список `STATIONS` в `__main__`.

Ожидаемое время обработки при `MAX_WORKERS=6` (GPU, 10–20 мин / станция):

| Станций | Батчей | Время |
|---|---|---|
| 1 | 1 | 10–20 мин |
| 6 | 1 | 10–20 мин |
| 8 | 2 | 20–40 мин |
| 27 | 5 | 50–100 мин |

#### `core/gpu_pipeline.py` — GPU-обёртка для точечных запусков

Загружает `legacy/cutter-v5.py` через `importlib` и вызывает `main_v10()`. Удобен для обработки отдельных станций вне основной конфигурации (например, вновь поступившие данные). Тот же паттерн initializer, тот же выходной каталог.

```bash
python core/gpu_pipeline.py
```

#### `core/cpu_pipeline.py` — CPU-параллельная обработка

Для машин без GPU. Загружает `detector.py` через importlib и принудительно переключает TF на CPU через `set_visible_devices([], 'GPU')`. Количество TF-потоков ограничивается на воркер, чтобы процессы не конкурировали за ядра.

```bash
python core/cpu_pipeline.py
```

По умолчанию: `MAX_WORKERS=8`, `TF_THREADS_PER_WORKER=4` (32 потока TF в сумме).

Ожидаемое время обработки при `MAX_WORKERS=8` (CPU, ~30 мин / станция):

| Станций | Батчей | Время |
|---|---|---|
| 1 | 1 | ~30 мин |
| 6 | 1 | ~30 мин |
| 8 | 1 | ~30 мин |
| 27 | 4 | ~2 часа |

Для сравнения по режимам (1 станция, 1 месяц):

| Режим | Время |
|---|---|
| GPU (RTX 4070, MAX_WORKERS=6) | 10–20 мин |
| CPU (MAX_WORKERS=8, 32 потока TF) | ~30 мин |

## Многостанционная ассоциация событий

После детекции на каждой станции по отдельности пики P-фаз коррелируются между станциями для подтверждения сетевых событий. Реализованы два ассоциатора.

### Сетевой ассоциатор (`core/associator.py`)

Все станции в едином пуле. Построен на `run_associator_v2()`:

- Группировка по **`p_arrival_time`** — физически точная опорная точка, а не начало 60-секундного окна (ошибка оригинального ассоциатора)
- **Скользящее окно** с шагом 30 с гарантирует, что каждое событие полностью попадает хотя бы в одно окно
- Дедупликация перекрывающихся кандидатов
- Опциональный фильтр `_coherent_subset()`: итеративно исключает станцию с наибольшим числом нарушений неравенства треугольника, не отбрасывая событие целиком

```bash
python core/associator.py
```

**Результат: 37/49 событий (75.5%), ~26 000 ассоциаций / месяц**

### Секторный ассоциатор (`core/sector_associator.py`)

Разбивает сеть на западный и восточный географические секторы, запускает сетевой ассоциатор в каждом секторе независимо, затем объединяет результаты с дедупликацией (события в пределах 30 с → оставляется то, у которого больше станций).

Подход существенно сокращает число ложных ассоциаций за счёт потери событий, чьи пики распределены между секторами.

```bash
python core/sector_associator.py
```

**Результат: 35/49 событий (71.4%), ~20 000 ассоциаций / месяц (−23% относительно сетевого)**

### Сравнение подходов

| Подход | Recall | Ассоциаций | Когда использовать |
|---|---|---|---|
| Сетевой ассоциатор | **37/49 = 75.5%** | ~26 000 | Максимизация числа обнаружений |
| Секторный ассоциатор | 35/49 = 71.4% | ~20 000 | Баланс recall и числа ассоциаций |

## Основные модули (`core/`)

| Модуль | Назначение |
|---|---|
| `detector.py` | Основной скрипт обработки. Читает SEED-файлы, нарезает 10-минутные сегменты, запускает in-memory инференс, пишет CSV на станцию. Полностью автономен. |
| `gpu_pipeline.py` | Параллельная GPU-обёртка для точечных запусков. Загружает legacy-пайплайн через importlib. |
| `cpu_pipeline.py` | Параллельная CPU-обёртка. Тот же интерфейс, TF принудительно на CPU, ограничены потоки на воркер. |
| `associator.py` | Сетевой ассоциатор. Читает CSV всех станций, применяет пороги стейджинга, запускает скользящее окно, выдаёт QuakeML XML + Y2000.phs. |
| `sector_associator.py` | Секторный ассоциатор. Разбивка Запад/Восток с перекрывающейся станцией. Объединяет вывод секторов с дедупликацией. |
| `validate_catalog.py` | Сравнение детекций одной станции с эталонным каталогом. Автоматически вычисляет поправку на P-время пробега. |
| `validate_associator.py` | Сравнение выходного XML ассоциатора с каталогом. Поправка на TT до ближайшей станции. |
| `threshold_tuner.py` | Сеточный поиск по порогам на уже готовых CSV — без повторного запуска модели. |
| `catalog_stats.py` | Анализ Гутенберга–Рихтера, оценка магнитуды полноты, распределение событий по расстоянию. |

## Результаты (январь 2024, 49 событий каталога)

> Все замеры времени получены на следующей конфигурации. Результаты на другом железе будут отличаться.
>
> **CPU:** AMD Ryzen 7 7400F (6 ядер, 3.7–4.7 ГГц, L3 32 МБ)
> **RAM:** 32 ГБ DDR5 6400 МГц CL30
> **SSD:** ADATA LEGEND 960 MAX 4 ТБ (чтение 7400 МБ/с, запись 6800 МБ/с)
> **GPU:** NVIDIA RTX 4070 12 ГБ

| Конфигурация | Recall | Ассоциаций |
|---|---|---|
| SOC (одна станция) | 26/49 = 53.1% | — |
| Сетевой ассоциатор, 10 станций | 36/49 = 73.5% | ~26 000 |
| **Сетевой ассоциатор, 12 станций** | **37/49 = 75.5%** | ~26 000 |
| Секторный ассоциатор, 12 станций | 35/49 = 71.4% | ~20 000 |

Каталог охватывает диапазон Ms от −0.1 до 3.8. EQT уверенно детектирует события до Ms ≈ −0.4. Число ассоциаций (~20–26 тыс./месяц) соответствует ожидаемой микросейсмичности: экстраполяция закона Гутенберга–Рихтера (b ≈ 0.7) предсказывает 1700–9000 событий/месяц при Ms ≥ −2.

## Возможные направления улучшения

### Ассоциатор
- **Межсекторный проход**: секторный ассоциатор теряет события, чьи пики распределены между секторами (например, Ms=2.3 от 25 января — 7 станций, но ни один сектор не набирает нужного числа). Третий проход по всем станциям с повышенным порогом (pair_n=5–6) позволит восстановить такие события без роста ложных ассоциаций
- **Адаптивный pair_n**: для событий на границе сети требовать больше подтверждающих станций
- **Точная настройка `_coherent_subset()`**: избирательное исключение шумящей станции вместо отбрасывания всего события

### Сеть станций
- **Восстановление NEUR**: систематические смещения P-пиков 20–35 с, вероятно, связаны с уходом часов или ошибкой в инструментальном отклике. Коррекция добавит ценную станцию для NE-кластера
- **Западное расширение**: GLDR (226 км), SUKR (231 км), ANN (244 км), TMNR (295 км) ещё не обработаны; улучшат покрытие западного сектора и снизят пропуски в зоне Мынтского роя
- **GRYR**: только 1 день данных в январе; полный месяц добавит промежуточное покрытие на 123 км в восточном направлении

### Модель и инференс
- **Неопределённость (MC Dropout)**: текущий пайплайн использует `model.predict()` (режим инференса, Dropout отключён). Истинный Monte Carlo Dropout требует `model(X, training=True)` — даст калиброванные оценки неопределённости при 5× росте времени инференса
- **Дообучение на региональных данных**: EQT обучен на глобальных данных; дообучение на кавказских записях потенциально улучшит чувствительность к региональным механизмам очагов и скоростной модели коры

## Установка

```bash
conda create -n eqt3 python=3.10
conda activate eqt3
conda install -c conda-forge cudatoolkit=11.2 cudnn=8.1.0
pip install tensorflow-gpu==2.10.0
pip install obspy "h5py==3.1.0" "numpy==1.19.2" scipy openpyxl
```

> **tensorflow-gpu** устанавливать через pip, не через conda (conda-версия давала hash mismatch).
> CUDA DLL должны быть в PATH — добавьте `$CONDA_PREFIX/Library/bin` через скрипт conda activate.d.
