# threads.py — описание

## Цель

Однострочный калькулятор: сколько потоков/процессов разумно занять под какую-то параллельную задачу (детектор, ассоциатор и т.п.), если хочется оставить машине запас — не 100% логических ядер, а заданную долю. Используется вручную, разово, чтобы прикинуть значение перед тем, как передать его флагом `--max-workers`/`--tf-threads-per-worker` в других файлах (`cpu_pipeline.py`, `gpu_pipeline.py`) — сам он никуда не встроен и результат никуда автоматически не передаёт.

---

## Как работает

```python
def get_threads_to_use(percent):
    value = percent / 100
    num_threads = os.cpu_count()
    used_threads = math.ceil(num_threads * value)
    ...
    return used_threads
```

`percent` — желаемая доля от `os.cpu_count()` (число логических ядер, с учётом hyperthreading, если он включён), в процентах. Результат округляется **вверх** (`math.ceil`) — при доле, не делящей число ядер нацело, лучше на один поток больше, чем меньше (легче загрузить одно ядро чуть сильнее, чем недобрать параллелизма). Печатает три строки (всего потоков / используется потоков) и возвращает `used_threads`.

## ⚠️ Побочный эффект при импорте

В конце файла — вызов на уровне модуля, не внутри `if __name__ == "__main__":`

```python
print(get_threads_to_use(80))
```

Это значит, что **сам факт `import threads`** (а не только запуск `python core/threads.py` напрямую) выполнит расчёт и распечатает результат для доли `80%` — жёстко зашитой, не параметра. Файл рассчитан на прямой запуск как маленький скрипт-калькулятор (`python core/threads.py`), а не на использование как модуль с чистым импортом функции без побочных эффектов.

На практике это не создаёт проблем только потому, что **никто его не импортирует** — см. ниже.

## Дублирование, а не переиспользование

`get_threads_to_use` определена ещё в двух местах в проекте — не как импорт из `core/threads.py`, а как независимая копия того же кода:

- `legacy/thread_executor.py` — своя копия функции, реально используется внутри самого этого legacy-файла.
- `legacy/gpu_pipeline.py` — своя копия функции, там вообще не вызывалась (мёртвый код). Убрана при переходе `core/gpu_pipeline.py` на CLI (2026-09-06, `production-plan.md` Трек 1, см. `core/gpu_pipeline.md`, раздел «Мёртвый код») — в текущем `core/gpu_pipeline.py` дубликата больше нет.

Ни один из этих файлов не импортирует функцию из `core/threads.py` — она нигде не используется как библиотека, только как самостоятельный скрипт для ручной прикидки числа.
