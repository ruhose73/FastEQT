# core/ — Основные модули обработки

Активные скрипты пайплайна. Запускаются из корня репозитория (`python core/<script>.py`) — либо напрямую, либо как библиотека, загружаемая другим скриптом через `importlib`/`import`.

Этот файл — краткий обзор с ориентирами. Подробное описание алгоритма, всех констант/CLI-флагов и найденных особенностей каждого скрипта — в соответствующем `core/<имя>.md`.

`detector.py`, `cpu_pipeline.py`, `gpu_pipeline.py`, `associator.py`, `sta_correction_estimator.py` (2026-09-06, `production-plan.md` Трек 1) конфигурируются флагами командной строки — `--help` на каждом даёт полный список; константы в начале файла остались только как значения по умолчанию для этих флагов. `threads.py` — разовый ручной калькулятор, CLI ему не нужен.

Более старые/заброшенные версии этих же скриптов — в `legacy/` (см. `legacy/README.md`), не здесь.

## Детекция

### `detector.py` — центральный модуль детектора

Читает суточные SEED-файлы одной станции, нарезает на перекрывающиеся 10-минутные сегменты, прогоняет через модель EQTransformer, пишет CSV детекций (P/S-пики, вероятности, SNR, опционально MC Dropout неопределённость). Полностью автономен — не зависит от `legacy/`.

Одна цепочка обработки (`process_station_v3` → `preproc_sequential_v5` → `worker_v4`, MC Dropout опционально) — используется и при прямом `python core/detector.py --stations ...`, и через `cpu_pipeline.py`/`gpu_pipeline.py` (см. `detector.md`). Список станций, пути и пороги предиктора (`detection_threshold`/`P_threshold`/`S_threshold`/`keepPS`/`allowonlyS`/`spLimit`/`batch_size` — раньше зашиты в теле `worker_v4`) — CLI-флаги по всей цепочке. Раньше существовала вторая, старая цепочка (`process_station`/`worker_v3`/`preprocessorV6_mem`) — удалена целиком (2026-09-06) как небезопасная для станций <90 Гц (см. `detector.md`), вместе с уже мёртвой `process_station_v2` и неиспользуемой константой `MAX_WORKERS`; предыдущая версия — `legacy/detector.py`.

→ подробности: `detector.md`

### `cpu_pipeline.py` / `gpu_pipeline.py` — параллельный запуск детектора на нескольких станциях

Обёртки над `detector.py`: поднимают пул процессов (`ProcessPoolExecutor` + `initializer`, модель грузится один раз на процесс), передают список станций/диапазон дат в `detector.process_station_v3()`. Разница между ними — только устройство: CPU-версия скрывает GPU и ограничивает TF-потоки под число ядер; GPU-версия настраивает `memory_growth` и упирается в VRAM, а не в CPU-ядра. Обе теперь принимают `--date-from`/`--date-to` (унифицировано — раньше `cpu_pipeline.py` брал только целый месяц/год) и `--stations`; `gpu_pipeline.py` также лишился неиспользуемой `get_threads_to_use()` (дублировала `core/threads.py`).

Обе пишут общий лог по сегментам (`data-in-memory/processing_log.csv`) в режиме перезаписи — при параллельной обработке нескольких станций сохраняется лог только последней завершившейся (известная гонка, не критична — основной CSV с детекциями per-станционный).

→ подробности: `cpu_pipeline.md`, `gpu_pipeline.md`

## Ассоциация

### `associator.py` — сетевой ассоциатор

Готовит per-станционный стейджинг (фильтр по порогам вероятности/SNR, три режима учёта MC Dropout неопределённости — `none`/`weight`/`filter`, см. `associator.md`), затем запускает `run_associator_v2` (`EQTransformer/utils/associator.py`) — скользящее окно по P-пикам, дедупликация, фильтр физической согласованности станций (`_coherent_subset`). На выходе — `associations.xml` (QuakeML), `Y2000.phs`, `traceNmae_dic.json`. Весь код обёрнут в `run_associator()` + CLI (раньше выполнялся построчно на верхнем уровне модуля) — предыдущая версия `legacy/associator_v3.py`.

→ подробности: `associator.md`

## Магнитуда (ML)

### `sta_correction_estimator.py` — станционные поправки для формулы ML

Сопоставляет каталожные события (`catalog.xlsx`) с ассоциациями, измеряет амплитуду S-волны на каждой станции, вычисляет поправку `S = Ms_каталог − ML_raw` и усредняет по станции (с IQR-детектором выбросов). Выход — CSV `station,S`, который принимает `ml_filter_v5.py` через `--sta-corrections`.

→ подробности: `sta_correction_estimator.md`

### `ml_filter_v5.py` — фильтрация ассоциаций по локальной магнитуде (актуальная версия)

Читает окна MSEED вокруг S-пиков, снимает инструментальный ответ, считает ML по формуле Дягилева и др. 2023 (формула 5б) для каждой станции события, агрегирует (медиана → σ-фильтр выбросов → среднее), фильтрует `associations.xml` по порогу ML.

`v5` — это продакшн-чистка `v4` (см. `production-plan.md`, Трек 1, п.1.1/1.3), не новый алгоритм: убран мёртвый legacy-путь агрегации (ratio-фильтр, был достижим только через ручную диагностику, `main()` его не вызывал), все константы формулы/порогов/окон вынесены из хардкода в CLI-флаги (дефолты не изменились). Содержательно ML для одного и того же входа v4 и v5 считают одинаково.

`ml_filter_v4.py` перенесён в `legacy/` (2026-09-06, см. `legacy/README.md`) — используйте `v5` для новых запусков.

→ подробности: `ml_filter_v5.md` (для истории — `legacy/ml_filter_v4.md`, описывает исходную версию до чистки)

## Валидация

### `validate_associator_v2.py` — сравнение ассоциаций с каталогом без гипоцентра

Оценивает время очага (T0) из разницы прихода P/S на каждой станции (S-P, без координат события — гипоцентр в пайплайне не вычисляется вообще), пятью разными способами агрегации; опционально считает ML (независимая реализация той же формулы, что в `ml_filter_v5.py`/`sta_correction_estimator.py` — константы отброса выбросов между тремя реализациями не совпадают, см. `validate_associator_v2.md`). Сравнивает с `catalog.xlsx`, считает recall.

Старая версия (`validate_associator.py`, сравнение по `event_start_time`-эквиваленту) — в `legacy/`; на неё раньше ссылался флаг `--validate` в `ml_filter_v4.py` (убран — реальная валидация всегда идёт этим файлом, отдельным запуском).

→ подробности: `validate_associator_v2.md`

## Экспорт бюллетеня

### `export_bul.py` — экспорт ассоциаций в бюллетень IMS1.0:SHORT

Переиспользует `validate_associator_v2.py` как модуль (не дублирует формулы) — та же оценка T0/ML, но без сравнения с каталогом: на выходе все события, прошедшие фильтры, в формате, похожем на официальные бюллетени ГС РАН (`bul/*.BUL`). Отсеивает нерегиональные станции по расстоянию, определяет регион события по ближайшей станции (StationXML).

→ подробности: `export_bul.md`

### `compare_bul.py` — сравнение двух бюллетеней `.BUL`

Читает два `.BUL`-файла напрямую как текст (не трогает XML/CSV пайплайна), сопоставляет события по времени и общим станциям. Обычно используется для сравнения выхода `export_bul.py` с официальным бюллетенем ГС РАН — контроль более строгий, чем сверка с `catalog.xlsx` (337 событий за весь 2024 год, малорепрезентативен).

→ подробности: `compare_bul.md`

## Утилиты

### `threads.py` — калькулятор числа потоков

`get_threads_to_use(percent)` — доля от `os.cpu_count()`, округление вверх. Разовый ручной расчёт перед тем, как проставить `--max-workers`/`--tf-threads-per-worker` в других файлах — сюда ничего не импортирует и никуда не встроен (функция продублирована, не переиспользована, в `legacy/thread_executor.py` и `legacy/gpu_pipeline.py` — в текущем `core/gpu_pipeline.py` убрана, см. `gpu_pipeline.md`).

→ подробности: `threads.md`
