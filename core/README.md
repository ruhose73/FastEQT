# core/ — Основные модули обработки

Все активные скрипты пайплайна. Запускаются из корня репозитория через `python core/<script>.py`.

> **Конфигурация:** все параметры запуска — список станций (`STATIONS`), число воркеров (`MAX_WORKERS`), число TF-потоков (`TF_THREADS_PER_WORKER`), целевой месяц/год (`TARGET_MONTH` / `TARGET_YEAR`), пути к данным — задаются в верхней части каждого скрипта в разделе конфигурации и легко изменяются под конкретную задачу без правки логики.

---

## Модули

### `detector.py` — Основной детектор (GPU, in-memory)

Центральный модуль всего пайплайна. Содержит все активные функции обработки сейсмических данных и является полностью автономным — не требует импорта из других скриптов проекта.

**Что делает:**
- Читает суточные SEED-файлы через ObsPy и нарезает их на 10-минутные сегменты с шагом 5 минут (50% перекрытие)
- Для каждого сегмента запускает предобработку (`preprocessorV6_mem`) и инференс модели EQT (`predictor_mem_non_hdf_load_model_v4`)
- Все данные обрабатываются в памяти — HDF5 на диск не пишется
- Пишет один CSV-файл результатов на станцию в `data-in-memory/output_gpu/{STATION}/`
- Ведёт лог обработки в `data-in-memory/processing_log.csv`

**`__main__`:** запускает параллельную обработку 12 станций через `ProcessPoolExecutor` (`MAX_WORKERS=3`). Модель загружается один раз на воркер через паттерн `initializer`.

**Ключевые функции:**

| Функция | Назначение |
|---|---|
| `load_model_cudnn_v2()` | Загружает модель EQT и патчит LSTM-ячейки для активации cuDNN |
| `_patch_lstm_inplace()` | Патчит `lstm.cell.recurrent_dropout = 0.0` и `implementation = 2` |
| `geofile_splitter_multi_chanels_v2()` | Генератор сегментов: один день → серия 10-мин сегментов, RAM ограничен |
| `worker_v3()` | Обрабатывает один сегмент: предобработка + инференс + постобработка |
| `preproc_sequential_v4()` | Потребляет генератор, пишет CSV, `gc.collect()` каждые 50 сегментов |
| `process_station()` | Точка входа для одной станции, принимает уже загруженную модель |

```bash
python core/detector.py
```

### `gpu_pipeline.py` — Параллельный GPU-обработчик (через legacy)

Обёртка для точечной обработки станций вне основной конфигурации `detector.py`. Загружает `legacy/cutter-v5.py` через `importlib` и вызывает `main_v10()`. Полезен когда нужно обработать несколько новых станций не меняя конфигурацию `detector.py`.

**Особенности:**
- Тот же паттерн `initializer` — модель грузится один раз на воркер
- `MAX_WORKERS=6`, GPU с включённым memory growth
- Выход — в `data-in-memory/output_gpu/` (тот же каталог, что и `detector.py`)
- Текущая конфигурация: NCK, SRGR, GOFR (станции, обработанные отдельно)

```bash
python core/gpu_pipeline.py
```

---

### `cpu_pipeline.py` — Параллельный CPU-обработчик

Версия детектора для машин без GPU. Загружает `detector.py` через `importlib` и вызывает `process_station()`. Принудительно скрывает GPU через `tf.config.set_visible_devices([], 'GPU')` и ограничивает число TF-потоков на воркер.

**Параметры:**
- `MAX_WORKERS = 8` — число параллельных процессов
- `TF_THREADS_PER_WORKER = 4` — TF-потоков на воркер (итого 32 потока)
- Выход — в `data-in-memory/output_cpu/`

**Ориентировочное время** (~30 мин / станция / месяц):

| Станций | Время |
|---|---|
| 1–8 | ~30 мин |
| 27 | ~2 часа |

```bash
python core/cpu_pipeline.py
```

### `associator.py` — Сетевой ассоциатор

Объединяет детекции всех станций в подтверждённые сетевые события. Использует `run_associator_v2()` из `EQTransformer/utils/associator.py`.

**Алгоритм:**
1. Читает CSV-детекции из `data-in-memory/output_gpu/{ST}/`
2. Применяет пороги стейджинга (DET ≥ 0.7, P ≥ 0.3, S ≥ 0.2, KEEP_PS=True)
3. Записывает отфильтрованные данные во временные staging-CSV
4. Запускает ассоциатор со скользящим окном (шаг 30 с) по `p_arrival_time`
5. Дедуплицирует перекрывающихся кандидатов
6. Автоматически удаляет устаревшие staging-директории удалённых станций

**Выход:** `data-in-memory/association_gpu/` (QuakeML XML, Y2000.phs, traceNmae_dic.json)

**Результат:** 37/49 событий каталога (75.5%), ~26 000 ассоциаций / месяц

```bash
python core/associator.py
```

### `sector_associator.py` — Секторный ассоциатор

Географически разделяет сеть на западный и восточный секторы и запускает ассоциацию независимо в каждом. Снижает число ложных ассоциаций за счёт уменьшения числа межстанционных пар.

**Секторы:**
- **Запад:** SOC, VSLR, GUZR, MRNR, SPGR, LABN, GOYR
- **Восток:** DOMR, SHA1, BEYR, PYA1, ZEI
- **Перекрытие:** GRYR (входит в оба сектора)

**Слияние:** события в пределах 30 с считаются одним — оставляется то, у которого больше станций.

**Выход:** `data-in-memory/association_gpu/sectors/` (XML по секторам + объединённый XML)

**Результат:** 35/49 событий (71.4%), ~20 000 ассоциаций / месяц

```bash
python core/sector_associator.py
```

### `validate_catalog.py` — Валидация детекций одной станции

Сравнивает CSV-детекции одной станции с эталонным каталогом землетрясений. Для каждого события вычисляет ожидаемое время прихода P-волны с учётом гипоцентрального расстояния и скорости Vp, затем ищет совпадение в детекциях в пределах заданного окна.

**Параметры CLI:**

```bash
python core/validate_catalog.py --detections data-in-memory/output_gpu/SOC/soc.csv --year 2024 --month 1
python core/validate_catalog.py --window 20 --vp 6.2 --min-mag 1.0
```

**Выход:** список найденных и пропущенных событий с указанием расстояния, времени пробега и отклонения.

---

### `validate_associator.py` — Валидация XML-ассоциатора

Сравнивает выходной QuakeML-файл ассоциатора с эталонным каталогом. Автоматически корректирует время события на время пробега P-волны до ближайшей станции (поскольку origin time в XML = время первого пика, а не время в очаге).

**Параметры CLI:**

```bash
python core/validate_associator.py --year 2024 --month 1
python core/validate_associator.py --assoc data-in-memory/association_gpu/sectors/merged/associations.xml --window 20
```

### `threshold_tuner.py` — Подбор порогов без перезапуска модели

Выполняет сеточный поиск по комбинациям порогов детекции (detection, P, S) на уже готовых CSV-детекциях. Позволяет найти оптимальные пороги без повторного запуска инференса (который занимает 20–30 мин).

**Алгоритм:** для каждой комбинации порогов фильтрует детекции, считает recall по каталогу, сортирует по убыванию recall и возрастанию числа детекций.

```bash
python core/threshold_tuner.py --detections data-in-memory/output_gpu/SOC/soc.csv
python core/threshold_tuner.py --det-steps 9 --p-steps 5 --s-steps 5 --year 2024 --month 1
```

### `catalog_stats.py` — Статистика каталога

Выводит распределение событий по магнитуде (шаг 0.5 Ms), оценку магнитуды полноты по закону Гутенберга–Рихтера и список событий января 2024 по расстоянию от SOC.

```bash
python core/catalog_stats.py
```

### `threads.py` — Утилита: расчёт числа потоков

Вспомогательная функция `get_threads_to_use(percent)` — вычисляет количество потоков как долю от числа логических ядер CPU. Используется при ручной настройке параллелизма.

### `_tmp_missed2.py` — Анализ пропущенных событий (временный)

Скрипт-черновик для изучения конкретных пропущенных событий каталога. Загружает каталог из Excel и выводит детали по заданному списку событий с аннотациями причин пропуска. Не является частью основного пайплайна.
