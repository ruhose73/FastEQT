# compare_bul.py — описание алгоритма

## Цель

Сравнивает два бюллетеня в формате **IMS1.0:SHORT/LONG** — эталонный (`--reference`, официальный `bul/*.BUL` от ГС РАН) и «наш» (`--candidate`, обычно выход `core/export_bul.py`) — по времени очага и составу станций, считает recall. В отличие от всех остальных скриптов пайплайна, **не трогает** XML/CSV/каталог — читает оба файла напрямую как текст в формате `.BUL`, используя ту же раскладку колонок Origin/Phase Block (IDC-3.4.1Rev1), что и `export_bul.py`.

Полезен для проверки «а насколько наш автоматический бюллетень на самом деле похож на официальный», а не только для внутренней метрики recall/ML пайплайна (`validate_associator_v2.py` сравнивает с `catalog.xlsx` — гораздо более скудным набором, 337 событий за весь 2024 год).

---

## Разбор `.BUL`-файла (`parse_bul`)

Простой построчный автомат состояний, без внешних библиотек парсинга:

1. Строка `EVENT <id> <регион>` начинает новое событие — предыдущее (если было) сохраняется в список.
2. Строка-заголовок, содержащая одновременно `Date`, `Time` и `Latitude` (заголовок Origin Block) — сигнал, что **следующая** строка содержит время очага; берутся фиксированные позиции `Date: [1:10]`, `Time: [12:22]` (`hh:mm:ss.ss`), парсятся в `datetime`.
3. Строка-заголовок, содержащая `Magnitude`, `Nsta` и `OrigID` (заголовок Magnitude Block) — следующая строка содержит значение магнитуды (`cols 7-10`, `f4.1`). Если на событие несколько строк магнитуды (разные агентства/типы) — берётся только **первая**, остальные пропускаются (обычно первая соответствует первичному origin).
4. Строка-заголовок, содержащая `Sta`, `Phase` и `ArrID` (заголовок Phase Block) — все последующие строки до пустой строки или следующего `EVENT` разбираются как строки фаз, код станции берётся из `[0:5]` и добавляется в множество станций события (`set`, то есть одна станция считается один раз, даже если у неё несколько фаз P/S).

Каждое событие в итоге сводится к четырём полям: `event_id`, `region`, `t0` (время очага, может быть `None`, если строка не распозналась), `stations` (множество кодов станций), `mag` (магнитуда или `None`).

## Сопоставление событий (`match_events`)

Жадное сопоставление «каждому reference — лучший подходящий candidate», независимо для каждого события reference:

1. Событие reference без распознанного `t0` сразу считается непойманным (`missed`) — сравнивать по станциям без времени не имеет смысла при большом количестве кандидатов.
2. Среди всех candidate с `|t_cand − t_ref| <= --window` (по умолчанию 60с) **и** числом общих станций (`reference.stations & candidate.stations`) `>= --min-shared` выбирается тот, что делит **больше всего** станций; при равенстве — **ближе по времени**.
3. Если подходящий candidate не нашёлся — событие reference попадает в `missed`.

⚠️ **Сопоставление не эксклюзивно**: один и тот же candidate может быть выбран как «лучший» для нескольких разных событий reference (ничего не помечает candidate как уже использованный и не убирает его из рассмотрения для следующих reference-событий). При тесно расположенных по времени реальных событиях это может задвоить совпадение — окно `--window`/`--min-shared` стоит подбирать с учётом этого.

## Отчёт и вывод

`print_report` — recall (`len(matched) / len(reference)`), статистика по найденным (среднее/макс `|dt|`, среднее число общих станций), таблица найденных (время reference, id, магнитуда, `dt`, число общих станций, `N` станций reference/candidate) и таблица непойманных (время, id, магнитуда, регион, число станций reference). `--show-missed` — на будущее (сейчас список непойманных печатается всегда, если он непустой; флаг фактически влияет только на сообщение "Все события reference найдены" для пустого списка).

`--out-csv` (`write_csv`) — та же информация построчно в CSV: `status` (`matched`/`missed`), поля reference и (если есть) candidate, `dt_sec`, число общих станций.

---

## Фильтрация перед сравнением

Применяется до `match_events`, в этом порядке:

1. `--ref-year`/`--ref-month` — фильтр reference по `t0` (события без `t0` при этом отсеиваются тоже).
2. `--min-mag` — фильтр reference по `mag >= порог`; события без магнитуды в бюллетене (`mag is None`) отбрасываются вместе с ниже-пороговыми — с явным подсчётом, сколько из отброшенных было именно «без магнитуды».
3. `--min-cand-mag` — то же для candidate: события без вычисленной ML тоже отбрасываются.

## Полный список аргументов CLI

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `--reference` | **обязателен** | эталонный бюллетень (`.BUL`) |
| `--candidate` | **обязателен** | сравниваемый бюллетень (`.BUL`) |
| `--window` | `60.0` с | допуск по времени для сопоставления |
| `--min-shared` | `1` | минимум общих станций для засчитывания совпадения |
| `--min-mag` | нет | фильтр reference по магнитуде (до сравнения) |
| `--min-cand-mag` | нет | фильтр candidate по ML (до сравнения) |
| `--ref-year` / `--ref-month` | нет | фильтр reference по времени (до сравнения) |
| `--show-missed` | выкл. | см. примечание выше — влияет только на сообщение при пустом списке непойманных |
| `--out-csv` | нет | путь для CSV-версии отчёта |

## Известные особенности

- Разбор `.BUL` полностью полагается на фиксированные колонки (`Date [1:10]`, `Time [12:22]`, `Sta [0:5]`) — если реальный официальный бюллетень использует чуть другую раскладку (не байт-в-байт совпадающую с той, что задокументирована в `export_bul.py`), строки молча не распознаются (`t0=None`/станция не добавляется), без явной ошибки.
- Сопоставление не эксклюзивно (см. предупреждение выше в разделе про `match_events`).
- Магнитуда события — только первая строка Magnitude Block; если у эталонного бюллетеня агентство расположило основную магнитуду не первой строкой, будет взята не та.
