# compare_bul.py — описание алгоритма

## Цель

Сравнивает два бюллетеня в формате **IMS1.0:SHORT/LONG** — эталонный (`--reference`, официальный `workspace/bulletin/input/*.BUL` от ГС РАН) и «наш» (`--candidate`, обычно выход `core/export_bul.py`) — по времени очага и составу станций, считает recall; с `--location-error` — ещё и ошибку локации. **Это основной инструмент оценки качества пайплайна** (рабочий порог — `--min-mag 1.5` по эталону). В отличие от всех остальных скриптов пайплайна, **не трогает** XML/CSV/каталог — читает оба файла напрямую как текст в формате `.BUL`, используя ту же раскладку колонок Origin/Phase Block (IDC-3.4.1Rev1), что и `export_bul.py`.

Полезен для проверки «а насколько наш автоматический бюллетень на самом деле похож на официальный», а не только для внутренней метрики recall/ML пайплайна (`validate_associator_v2.py` сравнивает с `catalog.xlsx` — гораздо более скудным набором, 337 событий за весь 2024 год).

---

## Разбор `.BUL`-файла (`parse_bul`)

Простой построчный автомат состояний, без внешних библиотек парсинга:

1. Строка `EVENT <id> <регион>` начинает новое событие — предыдущее (если было) сохраняется в список.
2. Строка-заголовок, содержащая одновременно `Date`, `Time` и `Latitude` (заголовок Origin Block) — сигнал, что **следующая** строка содержит время очага; берутся фиксированные позиции `Date: [1:10]`, `Time: [12:22]` (`hh:mm:ss.ss`), парсятся в `datetime`.
3. Строка-заголовок, содержащая `Magnitude`, `Nsta` и `OrigID` (заголовок Magnitude Block) — следующая строка содержит значение магнитуды (`cols 7-10`, `f4.1`). Если на событие несколько строк магнитуды (разные агентства/типы) — берётся только **первая**, остальные пропускаются (обычно первая соответствует первичному origin).
4. Строка-заголовок, содержащая `Sta`, `Phase` и `ArrID` (заголовок Phase Block) — все последующие строки до пустой строки или следующего `EVENT` разбираются как строки фаз, код станции берётся из `[0:5]` и добавляется в множество станций события (`set`, то есть одна станция считается один раз, даже если у неё несколько фаз P/S).

Каждое событие в итоге сводится к четырём полям: `event_id`, `region`, `t0` (время очага, может быть `None`, если строка не распозналась), `stations` (множество кодов станций), `mag` (магнитуда или `None`).

## Сопоставление событий (`match_events`)

Жадное сопоставление «каждому reference — лучший подходящий candidate», независимо для каждого события reference:

1. Событие reference без распознанного `t0` сразу считается непойманным (`missed`) — сравнивать по станциям без времени не имеет смысла при большом количестве кандидатов.
2. Среди всех candidate с `|t_cand − t_ref| <= --window` (по умолчанию 60с) **и** числом общих станций (`reference.stations & candidate.stations`) `>= --min-shared` выбирается тот, что делит **больше всего** станций; при равенстве — **ближе по времени**.
3. Если подходящий candidate не нашёлся — событие reference попадает в `missed`.

### `--ref-mag-type kp` — магнитуда эталона из энергетического класса (2026-10-07)

**MPVA и наша ML — разные шкалы.** MPVA (ГС РАН) — магнитуда по амплитуде P-волны с калибровкой для Кавказа, по смыслу близка к mb; соотношение с MLH (Кондорская и др., 1993): MLH = 1.59·MPVA − 3.67. Наша ML (`ml_filter_v5.py`, формула Дягилева) в среднем на ~1.0–1.1 ниже MPVA, и это не ошибка измерения: тот же сдвиг дают другая полоса, окно, обе горизонтали и стандартная шкала Вуда–Андерсона/IASPEI (`context/scratch/ml_scale_test.py`).

**Шкала, сопоставимая с нашей ML,** — магнитуда из энергетического класса по формуле Раутиан K = 4 + 1.8·M, то есть M = (K − 4)/1.8. Именно так получена колонка Ms в `catalog.xlsx` (проверено на 48 событиях 2024 года, общих с бюллетенем: MPVA и K совпадают, Ms = (Kp − 4)/1.8, MPVA − Ms ≈ +1.24 — `context/scratch/catalog_vs_bul.py`). Наша ML ≈ M_K + 0.1…0.2. Энергетический класс ГС РАН пишет у каждого события (`(#PARAM Energy_class=…)`, читается `parse_bul_energy_class()`; берётся первый — у первого Origin), в том числе у событий без MPVA.

Май 2024: событий в бюллетене 67, MPVA есть у 46, класс K — у всех 67, и все 67 имеют M_K ≥ 1.5 (самые слабые 21 — как раз без MPVA). Recall (≥ 1 / ≥ 4 общих станций): «как раньше» (ML ≥ 1.5 по всем станциям) — 37/36 из 46 по MPVA, но 43/42 из 67 по K; `ml_filter_v5 --ml-stations consistent` — 39/38 из 46 и 45/44 из 67. По интервалам M_K (вариант `consistent`, ≥ 4 станций): 1.5–2.0 — 16 из 28, 2.0–2.5 — 17 из 25, ≥ 2.5 — 11 из 14.

### `--match-mode location` — сопоставление по месту (2026-10-07)

Альтернатива общим станциям: состав станций у нас и в бюллетене может различаться. Если координаты есть **у обоих** событий (у нашего — после `export_bul.py --locator-mode enrich|filter`), совпадение = `|dt| <= --window` **и** расстояние между эпицентрами `<= --max-dist-km` (default 50); общие станции не нужны. Если координат нет хотя бы у одного — `--no-coords-match`: `stations` (default, окно + `--min-shared` общих станций, как обычно) или `time` (только окно). Среди подходящих candidate выбирается совпавший по месту (ближайший по расстоянию), иначе ближайший по времени. В выводе — сколько совпадений получено по месту и сколько без координат. `match_events()` не менялся (`match_events_v2()` рядом).

Май 2024, `--min-mag 1.5`, наш `.BUL` после `enrich`: `stations` — 37/46; `location` (50 км) — 32/46 с любым `--no-coords-match` (5 найденных событий с ошибкой локации > 100 км по месту не совпадают); `location` с 1000 км и `time` (то есть фактически только время) — 37/46. То есть сейчас ни одно событие не теряется из-за несовпадения станций, а 9 пропущенных не имеют нашего события в окне ±60 с вообще.

`--loc-good-only` (с `--match-mode location`) — по месту сопоставляются только наши события с **хорошим** решением локатора: `Err depth > --loc-min-err-depth` (default 0.001; 0 — упор глубины в границу таблицы годографов) и `RMS < --loc-max-rms` (default 2.0 с). Оба значения читаются из нашего `.BUL` (колонки RMS 31–35 и Err depth 78–82, `parse_bul_origins()`). Событие с плохим решением сопоставляется как событие без координат (`--no-coords-match`), чтобы плохая локация не превращала найденное событие в «не найденное». Май 2024 (`enrich`, вход LOCSAT — `--out-xml-inliers`, ≥ 4 станций): с `--loc-good-only` recall совпадает с режимом `stations` (37/46 и 36/46), из них 17 совпадений по месту; без него — 32/46 и 31/46.

⚠️ **Сопоставление не эксклюзивно**: один и тот же candidate может быть выбран как «лучший» для нескольких разных событий reference (ничего не помечает candidate как уже использованный и не убирает его из рассмотрения для следующих reference-событий). При тесно расположенных по времени реальных событиях это может задвоить совпадение — окно `--window`/`--min-shared` стоит подбирать с учётом этого.

## Отчёт и вывод

`print_report` — recall (`len(matched) / len(reference)`), статистика по найденным (среднее/макс `|dt|`, среднее число общих станций), таблица найденных (время reference, id, магнитуда, `dt`, число общих станций, `N` станций reference/candidate) и таблица непойманных (время, id, магнитуда, регион, число станций reference). `--show-missed` — на будущее (сейчас список непойманных печатается всегда, если он непустой; флаг фактически влияет только на сообщение "Все события reference найдены" для пустого списка).

`--out-csv` (`write_csv`) — та же информация построчно в CSV: `status` (`matched`/`missed`), поля reference и (если есть) candidate, `dt_sec`, число общих станций.

### `--location-error` — ошибка локации (2026-10-07)

Дополнительный отчёт после основного: для совпавших событий, у которых координаты есть **в обоих** бюллетенях, — ошибка эпицентра (км, по сфере) и глубины (`candidate − reference`, км). Сводка: медиана/максимум ошибки эпицентра, сколько событий в пределах 10 км, медиана ошибки глубины; затем таблица по событиям. На recall и на основной вывод не влияет — без флага вывод побайтово прежний.

Координаты у нашего бюллетеня есть только после `core/export_bul.py --locator-mode enrich|filter` (из `core/locator.py`), и только у событий с сошедшимся решением. Читаются отдельной функцией `parse_bul_origins()` из первой строки Origin Block каждого события (тот же «первый Origin», что и `t0` в `parse_bul()`): Latitude — колонки 37–44, Longitude — 46–54, Depth — 72–76 (1-индексация; позиции сверены по реальным бюллетеням ГС РАН и ISC, см. `export_bul.md`). `parse_bul()` не менялся.

Май 2024, `--min-mag 1.5`, наш `.BUL` после `enrich`: координаты есть у 23 из 37 совпавших, медиана ошибки эпицентра 7.7 км, 13 из 23 в пределах 10 км. Большие ошибки (100–660 км) — события, где LOCSAT сошёлся, но глубина упёрлась в границу таблицы годографов (0 или 750 км): `enrich` пишет координаты любого сошедшегося решения, без проверки качества.

## Фильтрация перед сравнением

Применяется до `match_events`, в этом порядке:

1. `--ref-year`/`--ref-month` — фильтр reference по `t0` (события без `t0` при этом отсеиваются тоже).
2. `--min-mag` — фильтр reference по `mag >= порог`; события без магнитуды в бюллетене (`mag is None`) отбрасываются вместе с ниже-пороговыми — с явным подсчётом, сколько из отброшенных было именно «без магнитуды».
3. `--min-cand-mag` — то же для candidate: события без вычисленной ML тоже отбрасываются.

## Полный список аргументов CLI

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `--reference` | **обязателен** | эталонный бюллетень (`.BUL`) |
| `--candidate` | **обязателен** | сравниваемый бюллетень (`.BUL`) |
| `--window` | `60.0` с | допуск по времени для сопоставления |
| `--min-shared` | `1` | минимум общих станций для засчитывания совпадения |
| `--min-mag` | нет | фильтр reference по магнитуде (до сравнения) |
| `--ref-mag-type` | `mpva` | какая магнитуда reference для `--min-mag`: `mpva` — первая строка Magnitude Block (у ГС РАН — MPVA, по P-волне); `kp` — из энергетического класса, M = (K − 4)/1.8 (см. ниже) |
| `--min-cand-mag` | нет | фильтр candidate по ML (до сравнения) |
| `--ref-year` / `--ref-month` | нет | фильтр reference по времени (до сравнения) |
| `--show-missed` | выкл. | см. примечание выше — влияет только на сообщение при пустом списке непойманных |
| `--out-csv` | нет | путь для CSV-версии отчёта (без колонок ошибки локации) |
| `--location-error` | выкл. | дополнительный отчёт об ошибке эпицентра/глубины по совпавшим событиям, см. выше |
| `--match-mode` | `stations` | `stations` (время + общие станции) или `location` (время + расстояние между эпицентрами), см. выше |
| `--max-dist-km` | `50` | с `--match-mode location`: максимальное расстояние между эпицентрами |
| `--no-coords-match` | `stations` | с `--match-mode location`: события без координат — `stations` или `time` |
| `--loc-good-only` | выкл. | с `--match-mode location`: по месту — только наши события с хорошим решением локатора, см. выше |
| `--loc-max-rms` / `--loc-min-err-depth` | `2.0` / `0.001` | пороги «хорошего» решения для `--loc-good-only` |

## Известные особенности

- Разбор `.BUL` полностью полагается на фиксированные колонки (`Date [1:10]`, `Time [12:22]`, `Sta [0:5]`) — если реальный официальный бюллетень использует чуть другую раскладку (не байт-в-байт совпадающую с той, что задокументирована в `export_bul.py`), строки молча не распознаются (`t0=None`/станция не добавляется), без явной ошибки.
- Сопоставление не эксклюзивно (см. предупреждение выше в разделе про `match_events`).
- Магнитуда события — только первая строка Magnitude Block; если у эталонного бюллетеня агентство расположило основную магнитуду не первой строкой, будет взята не та.
